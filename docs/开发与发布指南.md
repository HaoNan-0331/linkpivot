# 开发与发布指南

面向本项目的开发、测试、打包与版本发布。打包与发布环节的坑位来自 v0.3.0（2026-08-14）实测复盘。

## 常用命令

```bash
npm run electron:dev       # 开发调试（构建 main/preload 后 concurrently 起 vite + electron）
npm test                   # 单元测试（plain vitest，tests/unit + src）
npm run test:electron      # 真路径测试（tests/electron，真实 native 模块）
npm run rebuild:native     # 按 Electron ABI 重建 better-sqlite3 / ssh2 / cpu-features
```

**⚠ test:electron 必须走 `npm run test:electron`**（`ELECTRON_RUN_AS_NODE=1 electron.exe` 运行以匹配 native ABI）。直接 `npx vitest` 走系统 node 会因 ABI 不匹配连锁失败，表面现象是 ssh2 报 `Unsupported algorithm: blowfish-cbc` 等批量 FAIL——这是运行时用错，不是代码回归。

调试期已验证的测试基线：单元 257 it + 真路径 32 it 全绿。

## 打包

```bash
npm run electron:build     # rebuild:native + tsc/vite/esbuild 构建 + electron-builder NSIS
```

产物输出在 **`release/`**：`网络拓扑管理工具 Setup X.Y.Z.exe` + blockmap。健康体积约 **110 MB**（win-unpacked 约 430 MB，NSIS mx=9 压缩）。

### 打包三坑（v0.3.0 实测）

1. **云盘 / 同步软件锁 dist/**：网盘类客户端同步大文件时会锁住打包中间产物（特征：`.nsis.7z` 旁边出现网盘的临时标记文件），导致下次打包 vite 清目录 EPERM 或 7za 报 `Cannot open N files`。**打包全程暂停目录同步，失败残留删干净再重试。**

2. **递归自吞（已在配置根治）**：历史上 electron-builder 输出与 vite renderer 同在 `dist/`，`files: dist/**/*` 会把上一次的打包产物打进下一次 asar，包体滚雪球（曾达 2.3 GB）撑爆 32 位 NSIS 的 2 GB mmap 上限（报 `File: failed creating mmap`）。现配置：`directories.output: release` 与 vite 解耦 + files 排除 `dist/win-unpacked|*.exe|*.7z|*.blockmap`。**若安装包体积异常膨胀，先怀疑此问题复发。**

3. **electron-builder 下载组件失败**：直连 GitHub 超时、走代理 TLS 握手断。解法——切 npmmirror 镜像直连：

   ```bash
   export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
   export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
   export NPM_CONFIG_REGISTRY="https://registry.npmmirror.com"
   ```

## 版本发布

打包版本系列（`0.x`）与 milestone 代号（`v1.x`）相互独立，映射关系记在内部 PROJECT.md。

1. **bump 版本**：`package.json` version → `X.Y.Z`，commit 风格 `chore(release): bump X.Y.Z for vX.Y milestone`
2. **打包**：`npm run electron:build`（见上，注意三坑）
3. **打 tag 并推送**：
   ```bash
   git tag -a vX.Y.Z -m "vX.Y.Z for vX.Y milestone"
   git -c http.proxy= -c https.proxy= push origin master vX.Y.Z
   ```
   （git 对 GitHub 走代理常 TLS 断，直连可用；下载类操作反而需要代理或镜像——两者别混）
4. **创建 Release**：
   ```bash
   cp "release/网络拓扑管理工具 Setup X.Y.Z.exe" /tmp/Setup.X.Y.Z.exe   # asset 命名惯例：Setup.X.Y.Z.exe
   gh release create vX.Y.Z /tmp/Setup.X.Y.Z.exe --title "vX.Y.Z（一句话主题）" --notes "..."
   ```
   描述用**面向用户的功能语言**（新增 / 优化 / 修复 / 升级建议 + compare 链接），不要写内部流程术语。
