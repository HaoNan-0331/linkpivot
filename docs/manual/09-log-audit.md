# 第 9 章 日志审计

## 功能概述

日志审计集中查询两类留痕：**AI 助手执行日志**（AI 在设备上执行命令的每条记录，含越权拦截审计）与 **AI 系统执行日志**（拓扑发现等系统级 AI 调用记录）。用于事后追溯「AI 干了什么、依据什么、结果如何」，以及安全审计（越权命令的处理结果）。

另有系统级运行日志（升级、备份等）写入后台系统日志表；本章是 AI 执行日志在当前版本的唯一查询入口。

## 界面布局

页面顶部一行页签：「AI 助手执行日志 | AI 系统执行日志」（默认前者）。每个页签为一张卡片：标题栏右侧「刷新」按钮，卡内为视图/结果筛选控件 + 表格（每页 10 条）。当前版本不提供按设备、时间的筛选（设计裁决不做，见「逐元素详解」）。

## 逐元素详解

### AI 助手执行日志页签

**视图切换**（分段控制器）：「全部 | 越权记录」两档。切到「越权记录」时自动刷新并追加二级筛选（「全部 | 用户确认放行 | 用户取消」）与两列附加列（处理结果 / 命中规则）。

| 元素 | 位置 | 触发条件 | 行为 | 规则与限制 |
| --- | --- | --- | --- | --- |
| 「全部/越权记录」分段器 | 卡片左上 | 点击切换 | 「全部」显示最近 200 条执行日志；「越权记录」仅显示命中越权规则（guardHits 非空）的记录 | 加载最近 200 条为上限 |
| 结果筛选分段器 | 越权视图内 | 点击 | 按「用户确认放行 / 用户取消」过滤越权记录 | — |
| 「刷新」按钮 | 卡片右上 | 点击 | 重新加载最新日志 | 按钮转圈 |
| 空态说明 | 越权视图无记录 | — | 「暂无越权记录——AI 命令未触发任何越权规则」或「『{筛选档}』筛选档暂无匹配记录（越权记录共 N 条）」，附解释文字：当 AI 命令目标超出对话设备集或发生跳转时会在此留下确认记录；未点「确认执行」的一切中断均记为用户取消 | — |

**表格列**（全部视图）：时间 / 设备 / 命令（超长省略）/ 状态 / 模式 / AI 原因（悬停看全文）/ 操作（「详情」链接）。

**状态标签**：已批准（绿）/ 已拒绝（红）/ 待确认（橙）/ 已执行（蓝）/ 执行失败（红）。

**模式标签**：确认（默认 confirm 模式）/ 智能（smart）/ 自动（紫）；越权视图下 auto 模式显示为「自动拦截」——全自动模式仍会被越权防线强制打断的标识。

**越权视图附加列**：

- 处理结果：「用户确认放行」绿 / 「用户取消」红。二态语义（强规则）：**唯一放行路径是当时点了「确认执行」**；点取消、关弹窗、切界面、关应用、确认超时等一切中断均记为「用户取消」。
- 命中规则：规则编号标签（红/金两色按级别），悬停显示该规则的解释说明。

**执行日志详情弹窗**（宽约 720 像素）：设备、执行命令、状态标签、模式标签（auto 模式附注「越权命令仍强制打断确认」），以及两个灰底等宽字体区块：「发送给 AI 的 Prompt」与「AI 原始响应」（空显示「(空)」），区块内部可滚动（最高约 200 像素）。

### AI 系统执行日志页签（拓扑发现）

记录拓扑自动发现等系统级 AI 调用。表格列：时间 / 状态（成功绿/失败红）/ 设备（参与设备名列表，超长省略）/ 错误信息（无则「-」）/ 操作（「详情」）。加载最近 100 条。

**系统日志详情弹窗**：设备、错误信息（红色，仅失败时）、发送给 AI 的 Prompt、AI 原始响应、解析结果（绿色区块，仅成功且有解析结果时显示）。

## 典型排查流程：追查一次可疑的 AI 命令

1. 切到「AI 助手执行日志」页签。预期表格显示最近的执行记录。
2. 切换视图到「越权记录」。预期列表只剩命中越权规则的记录；空列表说明近期无越权命中。
3. 需要锁定特定结果时，用二级筛选选「用户确认放行」或「用户取消」。
4. 找到目标记录，点行尾「详情」。预期弹窗展示：设备名、完整命令、状态、模式，以及发送给 AI 的 Prompt 与 AI 原始响应两个区块。
5. 核对三点：命令是否合理、AI 原因是否与命令一致、当时用户侧的处理（放行/取消）是否符合预期。命中规则列（越权视图）悬停可看规则解释。

## 执行日志字段说明

| 字段 | 含义 |
| --- | --- |
| 时间 | 记录生成时间（本机时区） |
| 设备 | 命令执行的目标设备名 |
| 命令 | 实际在设备上执行的命令原文（超长省略，详情可见全文） |
| 状态 | 已批准 / 已拒绝 / 待确认 / 已执行 / 执行失败 |
| 模式 | 触发时的执行模式：确认（confirm）/ 智能（smart）/ 自动（auto） |
| AI 原因 | AI 提议执行该命令的理由摘要 |
| 处理结果（越权视图） | 用户确认放行 / 用户取消 |
| 命中规则（越权视图） | 越权判定命中的规则编号，悬停看解释 |
| Prompt / AI 响应 | 详情弹窗内的完整上下文与 AI 原始回复 |

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 记录范围 | AI 每次在设备上执行命令都会留痕（无论成功失败）；拓扑发现的 AI 调用单独入系统日志 |
| 加载上限 | 执行日志取最近 200 条、系统日志取最近 100 条；更早记录保留在库中（受保留策略约束） |
| 保留策略 | 日志默认保留 90 天（prompt 与 AI 响应字段加密存储） |
| 越权终态语义 | 未点「确认执行」的一切中断统一记「用户取消」；界面短暂显示的待确认在后台对账后同样订正为取消 |
| 敏感内容 | Prompt/AI 响应原文仅在本页详情弹窗中展示，用于审计（当前版本设置页未挂载独立查看器，本页是唯一查询入口） |
| 时间显示 | 按本机时区格式化 |

## 常见问题

**Q1：模式列的「自动拦截」是什么意思？**
表示该记录产生时执行模式为全自动（auto），但命令命中越权规则被强制打断转为人工确认——全自动不代表越权免检。

**Q2：我没点过取消，为什么处理结果是「用户取消」？**
除点「确认执行」外的任何收尾（点取消、关闭弹窗、切换页面、退出应用、确认超时）都归为用户取消，这是审计口径，保证「放行必有显式动作」。

**Q3：怎么看 AI 当时为什么执行这条命令？**
点「详情」，「发送给 AI 的 Prompt」是当时的上下文与指令，「AI 原始响应」包含 AI 的原话与理由（AI 原因列是其摘要）。

**Q4：日志会占满磁盘吗？**
日志默认保留 90 天自动清理，且正文字段加密落库，容量可控。

**Q5：为什么有些记录的状态是「执行失败」？**
命令已获批准并执行，但在设备上执行出错（如设备返回错误、超时），详情中的 AI 原始响应可看到设备输出。

**Q6：表格只显示最近 200 条，更早的怎么查？**
本页定位日常审计，取最近记录；更早的历史仍在库中按保留策略保存，需要长期归档请定期核对，或联系维护者按数据库导出方式处理。

**Q7：「待确认」状态的记录一直不变？**
待确认是短暂中间态（等待用户在 AI 对话中处理确认面板）；用户处理后状态更新为已批准/已拒绝；若当时会话被中断，后台对账会将其终态化，刷新即可看到最终状态。

## 与设置页日志查看器的关系

日志审计页是 AI 执行日志的唯一查询入口（当前版本系统设置页未挂载独立的日志查看器）。本章两个页签已覆盖调试与审计两类场景：追提示词问题看详情弹窗的 Prompt/AI 响应原文，追安全问题用「越权记录」视图。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 执行日志 | AI 在设备上执行命令的逐条留痕记录 |
| 系统日志 | 拓扑发现等系统级 AI 调用的留痕记录 |
| 越权记录 | 命令命中越权防护规则的执行日志子集 |
| 命中规则 | 越权判定触发的具体规则编号及解释 |
| 用户确认放行 | 在确认弹窗显式点「确认执行」的唯一放行路径 |
| 用户取消 | 除确认放行外一切中断的统一审计终态 |
| Prompt 留痕 | 每次调用发给 AI 的完整上下文原文记录 |
| 保留策略 | 日志自动清理期限（默认 90 天） |
| 分段控制器 | 一组互斥选项的切换控件（如「全部/越权记录」） |
| 自动拦截 | auto 执行模式下仍被越权防线强制打断的记录标识 |
| 对账 | 后台把中断的待确认记录订正为最终状态的过程 |
| 解析结果 | 系统日志详情中 AI 响应被解析后的结构化输出展示 |
