# 第 1 章 产品概述

## 灵枢是什么

灵枢（LinkPivot，本项目英文名）是一个运行在 Windows 上的网络拓扑管理桌面工具，面向运维人员。它把日常网络运维中分散在多个工具里的工作收进一个应用：

- **看得见拓扑**：以可视化画布呈现网络设备与它们之间的连接关系，支持自动发现与自动布局。
- **连得上设备**：在同一界面里远程连接并操控设备，支持 SSH / Telnet / Web / RDP 四类远程通道。
- **有 AI 辅助**：内置 AI 助手，能读取你授权的知识库与经验库资料、在白名单约束下执行运维命令，并把有价值的对话沉淀成可复用的经验条目。
- **管得住资料**：设备台账、运维知识库、经验库、IP/MAC 监控数据全部存在本机数据库中。

灵枢是单机桌面软件（基于 Electron 技术构建，即用一个浏览器内核包装的本地应用），不依赖服务端部署，数据不上传云端。

## 七大功能模块

登录后主界面左侧的导航栏（侧边栏）从上到下依次为七个模块：

| 模块 | 用途 |
| --- | --- |
| 拓扑管理 | 可视化网络拓扑：节点摆放、连线、自动发现、自动布局 |
| 设备管理 | 设备台账：增删改查、四类通道凭证、测试连接、复制设备 |
| IP 管理 | 网段管理、ARP 采集、IP/MAC 异常检测、OUI 厂商识别 |
| AI 助手 | AI 对话、命令执行审批、知识/经验检索、经验起草 |
| 知识库 | 文档入库与解析、全文检索、经验库浏览与维护 |
| 日志审计 | AI 执行日志与系统日志的查询、筛选 |
| 系统设置 | AI 模型配置、提示词、命令白名单、MCP、执行模式 |

各模块的逐元素详解见第 4～11 章对应章节。

## 核心概念

以下概念贯穿全手册，首次出现处均给出通俗解释。

### 设备

设备是灵枢里一切管理对象的统称：交换机、路由器、防火墙、服务器等。每台设备有一条台账记录（名称、IP 地址、厂商、型号、位置、备注等），以及若干远程通道凭证（见下）。界面上的拓扑节点就是设备。

### 拓扑

拓扑指网络设备之间「谁连着谁」的关系图。灵枢用画布（基于 React Flow 图形库渲染，支持缩放、拖拽、框选的交互式图形区域）呈现：一台设备是一个节点，一条连接关系是一条连线，连线上可标注接口名称。拓扑可以从空白手动搭建，也可以通过「自动发现」功能登录到一台设备上采集邻居信息后自动生成。

### 远程通道

远程通道指灵枢连到一台设备所用的协议方式，共四类：

| 通道 | 说明 | 典型用途 |
| --- | --- | --- |
| SSH | 加密的命令行登录（支持密钥与密码两种认证方式） | 交换机/路由器/Linux 主机命令行 |
| Telnet | 明文的命令行登录 | 只支持 Telnet 的老旧设备 |
| Web | 用系统浏览器打开设备管理页面 | 网页管理的设备 |
| RDP | Windows 远程桌面（生成 .rdp 连接文件或调用 FreeRDP） | Windows 服务器图形界面 |

一台设备可以同时配置多类通道（例如既有 SSH 又有 Web），连接时再选择用哪一类。详见 [第 11 章 远程终端](./11-remote-terminal.md)。

### AI 助手

AI 助手是一个对话式运维助手。它的工作方式是「分档预取 + 受控执行」：

- **分档预取**：根据你选择的设备能力档位，AI 在回答前先检索知识库文档、经验库条目、设备实时数据，把检索到的内容作为上下文再作答；检索到的来源会以徽章形式展示，可点击回查。（预取默认关闭，可在 AI 助手页输入行首齿轮「检索设置」中开启，见第 7 章）
- **受控执行**：AI 提议在设备上执行的命令必须通过命令白名单校验；白名单内的命令按执行模式（confirm 需确认 / auto 自动）执行，越权命令会被拦截并要求强确认。
- **经验起草**：一次有价值的对话可以一键发起「经验总结」，AI 起草经验条目，经你人工确认后进入经验库，下次遇到同类问题可直接复用。

详见 [第 7 章 AI 助手](./07-ai-assistant.md)。

### 知识库

知识库用于管理运维文档：支持导入 PDF / DOCX 等格式，入库后自动解析成文本块并建全文索引（FTS5，SQLite 内置的全文检索引擎，可像搜索引擎一样按关键词查文档）；之后 AI 回答问题或你在界面上检索时都能命中这些内容。支持图片识别（对文档中的图片做多模态识别，生成文字描述后同样可检索）。

### 经验库

经验库是知识库的一个子页，存放结构化的运维经验条目：适用设备、故障现象、处理步骤、严重级别、标签等。经验条目两个来源：手动新建，或由 AI 从对话中起草后经人工确认发布。经验条目有生效/失效状态与「最后验证时间」，AI 复用一条经验前会校验其是否仍有效。

### IP 监控

IP 监控围绕「网段内的 IP 与 MAC 地址」展开：先在「网段」子页登记你要关注的 CIDR 网段（形如 192.0.2.0/24 的地址段），再通过 ARP 采集（ARP 是设备用来把 IP 地址映射到 MAC 地址的网络协议，登录到网关设备上执行 arp 相关命令即可拿到整网段的 IP-MAC 对照表）周期性或手动采集数据，系统对比历史数据自动发现异常（新出现的 IP、IP 换了 MAC、IP 消失等），并可按 OUI（IEEE 分配给网卡厂商的编号段，可据此识别网卡厂商）识别设备厂商。

## 安全机制通俗说明

灵枢的安全设计围绕两件事：**凭证不泄露**、**命令不乱跑**。

### 凭证加密存储

你在设备表单里填写的 SSH/Telnet 密码、RDP 密码等敏感信息，不会以明文存进数据库，而是逐字段用 AES-256-GCM 加密（一种业界标准的高强度加密算法，可以理解为给每个字段配一个只有本机能打开的保险箱）后再落库。界面上回显时只显示「已存 ****尾4」这样的脱敏形式——永远看不到完整密码。

### 主密钥绑定机器

所有加密字段共用一把主密钥（masterKey）。主密钥本身落盘时又经 Windows DPAPI（Windows 系统提供的、与当前用户账户绑定的加密保管机制）保护。效果是：**把数据库文件和密钥文件拷到别的电脑、或换一个 Windows 账户打开，都无法解密你的凭证**。因此在做整机迁移/备份时，需要连同用户数据目录一起迁移（见第 2 章「数据存放位置」）。

### IPC 鉴权

界面（渲染进程）与后台（主进程）之间的每一个内部接口调用都经过登录态校验：未登录状态下，除登录/初始化相关的少量接口外全部拒绝。接口报错时返回给界面的错误信息会自动脱敏，不泄露 SQL 语句、磁盘路径等内部细节。

### 命令白名单

AI 或远程执行链路里出现的每一条命令，执行前都必须通过命令安全校验（`commandSafety`）：先拦截分隔符注入，再比对黑名单首词、白名单首词。黑名单是一组内置的危险命令首词（shutdown、reboot、reset、reload、erase、delete、write、save、commit、system-view、configure、interface、vlan、undo、password 等，覆盖关机重启、进入配置模式、删除覆写类高危操作），固定不可查看或修改，且优先于白名单——即使把这类词加进白名单也一律拦截。白名单之外的非黑名单命令一律视为越权，触发拦截与强确认流程，不会静默执行。白名单内容可在系统设置中维护（见 [第 10 章 系统设置](./10-settings.md)）。

## 数据存放位置

灵枢的所有数据（设备台账、拓扑、凭证密文、知识库文档、日志）都存放在本机用户数据目录下的 SQLite 数据库文件中，不联网上传。数据库自带定期备份（双桶轮换），升级迁移前还会再做一次安全备份。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| Electron | 把浏览器内核与网页技术打包成桌面应用的技术框架，灵枢基于它构建 |
| 节点 | 拓扑画布上代表一台设备的图形块 |
| 连线 | 拓扑画布上代表两台设备间连接关系的线 |
| 画布 | 拓扑页中间可缩放、可拖拽的图形区域（React Flow 渲染） |
| 通道 | 灵枢连到设备所用的协议方式：SSH / Telnet / Web / RDP 四类 |
| 凭证 | 登录设备所需的账号、密码、密钥等敏感信息 |
| 脱敏 | 界面上以「****尾4」等形式隐藏敏感内容完整值的展示方式 |
| AES-256-GCM | 业界标准的高强度对称加密算法，灵枢用它加密每个敏感字段 |
| DPAPI | Windows 的用户级加密保管机制，主密钥经它保护后绑定本机本账户 |
| masterKey | 所有加密字段共用的根密钥，经 DPAPI 加密后落盘 |
| 分档预取 | AI 按所选设备的能力档位，在回答前先检索知识库/经验库/实时数据 |
| 白名单 | 允许 AI 执行的命令首词清单，清单外命令一律拦截 |
| FTS5 | SQLite 内置的全文检索引擎，知识库检索基于它 |
| OUI | 网卡厂商编号段，用于从 MAC 地址识别厂商 |
| ARP | 把 IP 地址映射到 MAC 地址的网络协议，采集整网段 IP-MAC 对照表用 |
| CIDR | 形如 192.0.2.0/24 的网段表示法，IP 管理的网段登记格式 |
| 经验条目 | 经验库中的结构化运维经验，含适用设备、现象、步骤、状态 |
