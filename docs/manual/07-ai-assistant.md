# 第 7 章 AI 助手

## 功能概述

AI 助手是对话式运维助手：按问题分档预取知识库/经验库/设备实时数据，在命令白名单约束下连续自主执行运维命令（越权命令强制人工确认），支持 MCP 工具扩展与经验沉淀（对话一键起草经验、人工确认入库）。执行模式与检索行为均可控。

使用前提：已在系统设置配置 AI 服务参数（API Key 等，见 [第 10 章](./10-settings.md)）。未配置时进入 AI 助手页显示提示「请先在「系统设置」中配置 AI 服务参数」。

## 界面布局

AI 助手页分为左右两区：

- **左区（会话列表，宽约 220 像素）**：顶部「新建会话」按钮，下方会话条目列表（可滚动）。每条会话一行：未读小圆点（如有）、会话标题、右侧删除图标。
- **右区（对话区）**：顶部标题「AI 助手」与右侧设备上下文选择器；中部消息滚动区（用户气泡右对齐浅蓝、AI 回复全宽裸 markdown、工具调用卡左对齐）；底部输入区（待确认命令在时会整体替换为审批面板）。

## 逐元素详解

### 会话列表（左区）

| 元素 | 位置 | 触发条件 | 行为 | 规则与限制 |
| --- | --- | --- | --- | --- |
| 「新建会话」按钮 | 左区顶部 | 点击 | 创建新会话并切换 | 在途时按钮转圈禁用（防连点双建）；新会话标题默认自动生成（取首条提问摘要） |
| 会话条目 | 列表行 | 点击 | 切换到该会话并加载历史消息 | 当前会话高亮（浅色底 + 左侧蓝条）；有未读回复的会话显示蓝色小圆点，点入即清除 |
| 删除图标 | 条目右端 | 点击 | 删除该会话及其消息 | 无确认弹窗，点击即删（删除失败提示「操作失败，数据已回滚无变化：…」并保持列表不变）；点击图标不会触发切换（事件隔离） |
| 未读小圆点 | 条目左端 | 回复完成且已切走时出现 | 提示哪个会话有新内容 | 当前正在看的会话不显示 |

**会话切换的隔离保证**：回复进行中切换会话不会串话或丢消息——「思考中」指示只出现在回复所属的会话；切回时在途的步骤卡会完整合并；正在其他会话回答时，当前会话输入框上方显示提示条「AI 正在其他会话回答中，输入已临时锁定」（输入全局锁，防止并发回复互相干扰）。

### 设备上下文选择器（对话区右上）

收起态为一行摘要框：未选时显示「点击选择目标设备」；已选 ≤3 台显示「已选：设备A、设备B」；>3 台显示「已选：设备A、设备B 等 N 台」。鼠标悬停展开选择浮层。

| 元素 | 位置 | 触发条件 | 行为 | 规则与限制 |
| --- | --- | --- | --- | --- |
| 搜索框「搜索设备名称」 | 浮层顶部 | 输入 | 按名称/IP 即时过滤设备列表 | 无匹配显示「无匹配设备」 |
| 设备勾选列表 | 搜索框下方 | 勾选/取消 | 增删目标设备（可多选） | 每行右侧显示能力标签（见下表）；列表最高约 200 像素滚动 |
| 多选警告标签 | 浮层底部 | 选中 >10 台 | 黄色提示「设备较多，AI 回答质量可能下降」 | 仅提示不阻止 |

**设备能力三档标注**（由设备通道配置自动派生，与 [第 5 章](./05-devices.md) 通道配置联动）：

| 标签 | 含义 | AI 可用能力 |
| --- | --- | --- |
| 「可执行」（绿） | 配置了 SSH 或 Telnet 通道 | 可在该设备执行命令、采集实时数据 |
| 「可调MCP」（蓝） | 绑定了 MCP 工具 | 可通过 MCP 工具操控 |
| 「仅问答」（灰） | 三者皆无 | 只参与知识/经验检索，不执行任何操作 |

双能力设备同时显示两个标签。

### 检索控制（输入行行首齿轮图标）

输入行最左侧的小齿轮按钮（无文字），点击向上弹出「检索设置」浮层。设置**全局持久**（跨会话、重启保留），控制 AI 回答前的资料检索行为：

| 元素 | 位置 | 行为 | 规则与限制 |
| --- | --- | --- | --- |
| 「预取注入」开关 | 浮层第一行 | 开 = 按问题档位在回答前自动检索并注入知识库/经验库/设备上下文；关 = 回答前不做预取（对话区不再出现 [预取] 卡） | 默认关 |
| 「补查模式」分段选择 | 浮层第二行 | 「强制补查」= AI 判断资料不足时必定发起补查；「智能补查」= 是否补查由 AI 自行判断 | 默认智能补查 |
| 说明两行小字 | 浮层底部 | 「智能模式下由 AI 判断是否补查」「故障排查问题始终强制补查」 | 硬约束：故障排查类问题无论设置如何都强制补查 |

改动即时保存，成功提示「检索设置已更新」。智能补查模式下，AI 决定不查的来源会在回复底部显示灰色标签「未查询：知识库」「未查询：经验库」「未查询：设备」等——不是出错，是「智能模式下由 AI 判断」的知情呈现；强制补查模式下不会出现这些标签。

**换词重查**（智能/强制两模式统一行为）：补查时若 AI 给出的检索关键词与本次对话已查过且未命中的关键词相同，系统不会用同一个词再查一遍，而是追加一轮「换词请求」要求 AI 换更具体的关键词重查。此时回复中会出现系统说明「知识库已用关键词 “xxx” 检索未命中，已请求换词重查」（经验库同理）。换词只发生一次——若换词后关键词仍与已查词相同，显示「本次不再检索（换词有界防循环）」，AI 以现有资料作答。

### 对话区消息

**消息形态**（不对称布局）：

- 用户消息：右对齐浅蓝圆角气泡，纯文本，气泡下方灰色小字时间。
- AI 回复：全宽无框 markdown 正文（markdown：用 # 号、星号等符号标记标题/加粗/列表的轻量排版格式，AI 输出的标准格式；支持表格、代码块、列表等渲染，HTML 与未知协议链接被安全过滤），附属块自上而下为：分档标签 → 硬停提示条 → 参考来源 → 来源徽章行 → 时间。
- 工具调用卡：左对齐的紧凑单行卡（见下节）。

**时间显示三档**：同天显示「HH:mm」；跨天显示「MM-DD」；跨年显示「YYYY-MM-DD」。

**分档标签**：AI 回复顶部显示本次问题所属档位（AI 自动判定），悬停显示该档预取的数据源清单：

| 档位 | 典型问题 | 本档预取 |
| --- | --- | --- |
| 故障排查 | 设备不通/报错/异常现象 | 知识库、经验库、设备上下文 |
| 配置查询 | 查配置/查状态类问题 | 知识库、经验库、设备上下文 |
| 知识问答 | 概念/原理类问题 | 知识库、经验库 |
| 巡检执行 | 巡检/批量查看类任务 | 知识库、经验库、设备上下文 |

**参考来源区**（虚线分隔，标题「参考来源：」）：列出回答引用的资料条目：

- 知识库条目：书图标 + 文档名 — 章节名；
- 经验条目：📖 前缀 + 经验标题，可点击打开经验详情弹窗；若经验中的命令已不在白名单，附黄色小标签「⚠ 命令已失支持」；
- 会话引用：💬 前缀 + 标题，点击可查看原始会话全文。

**来源徽章行**（AI 自主执行轨迹的知情呈现）：底部显示各类来源的汇总徽章「📚 知识库 ×N」「📗 经验 ×N」「🔧 设备 ×N」「🔧 工具 ×N」（数量为零的类型不显示）。点击徽章展开逐条明细，经验条目可点开详情。徽章区还可能显示：

- 灰色「未查询实时数据」：本轮明确没有查询任何实时数据（零检索零执行的诚实声明）；
- 灰色「未查询：{来源}」：智能补查模式下 AI 决定不查的来源逐个标注；
- 灰色小字补查记录：补查未命中或设备未查的知情说明。

**硬停提示条**（黄色）：任务被手动停止时显示「任务进行中被手动停止，未生成总结；已执行步骤保留在上方。」

**思考中指示**：回复进行中显示「思考中…」扫字动画；AI 自主任务（agent）运行中旁边常驻红色「停止」小按钮——点击立即中止，无二次确认。

### 工具调用卡（步骤卡）

AI 的每个动作（执行命令/检索知识库/检索经验库/调用 MCP 工具）显示为一张 24 像素高的单行卡：左侧状态图标或状态点 → 状态词 → 动作标题 → 单行截断摘要 → 行尾时间。点击整行（或聚焦后按 Enter/Space）原地展开为上下两个区：调用参数（IN）与原始结果（OUT），各自独立滚动。

**状态七态**：

| 状态词 | 含义 |
| --- | --- |
| 执行中 | 正在执行（带扫光动画） |
| 重试中 | 失败后自动重试（带扫光动画） |
| 完成 | 成功结束 |
| 失败 | 执行出错（仅状态词与摘要红字，卡片本身不变红） |
| 已熔断 | 连续失败次数过多被熔断保护 |
| 冷却中 | 熔断后的冷却等待 |
| 已中断 | 被用户停止或会话中断 |

旧格式记录无七态信息时按结果映射为「完成/超时/失败」（「超时」是旧格式记录的映射标签，不在七态之列）。超时的固定原因文案：「工具服务 60 秒内未响应，已自动中断」。

**动作标题**（可带前缀与通道后缀）：

- 「[预取] 检索知识库」「[预取] 检索经验库」：回答前的分档预取；
- 「[补查] 检索知识库」等：回答中途的补充检索；
- 「在 {设备名} 执行命令 · SSH」（或 · TELNET）：设备命令，后缀标明执行通道；
- 「调用工具 {工具名}」：MCP 工具调用。

### 命令审批面板（待确认命令出现时替换输入区）

当 AI 提议的命令需要确认时，输入区被琥珀色描边的审批面板接管（面板不消失无法继续对话）。结构：顶部琥珀条「等待审批」（左侧圆点）→ 可滚动命令区（最高约 336 像素，键盘可 Tab 进入滚动）→ 底部按钮行。

**普通确认分支**（confirm 模式下的白名单命令）：

- AI 说明段：AI 解释为什么要执行这些命令；
- 「待执行命令:」小节：逐条列出「[设备名] 命令原文」（等宽字体）；
- 「已拒绝命令:」小节（如有）：白名单校验未过被自动拒绝的命令与拒绝原因（不会执行）。

**越权确认分支**（命令命中越权防护规则时，警示更强）：

- 标题「越权确认（N 条命中 / 共 M 条命令）」；
- 「AI 命令命中 N 条安全规则，请核对目标后确认：」；
- 「预期目标 / 实际目标」对照卡：左侧是你选定的设备范围，右侧是命令实际指向的目标，不一致正是越权拦截的意义（三类典型场景：命令目标超出对话所选设备集、AI 发生设备跳转、MCP 工具参数携带敏感目标）；
- 命中规则列表：规则编号标签（红色=高危级、金色=白名单外）+ 规则解释 + 对应命令原文（红底等宽展示）；
- 「常规命令（无越权风险）」分节：同一批中未命中的命令（蓝标签）；
- 「已拒绝命令（N 条，不会执行）」分节（如有）。

**按钮**（面板唯一出口，无任何绕过入口）：

- 「拒绝执行」：拒绝全部待执行命令（静止时中性色，悬停变红）；
- 「确认执行」：放行待执行命令（越权场景下点击即视为「用户确认放行」，会记入日志审计）；
- 提交期间两按钮均转圈禁用。

审批结果可在 [第 9 章 日志审计](./09-log-audit.md) 追溯。

### 输入区

| 元素 | 位置 | 触发条件 | 行为 | 规则与限制 |
| --- | --- | --- | --- | --- |
| 检索设置齿轮按钮 | 行首 | 点击 | 打开检索设置浮层 | 见上文 |
| 输入框 | 行中部 | 输入 | 多行文本（1~4 行自适应） | 占位提示「输入消息... (Enter 发送, Shift+Enter 换行)」；回复进行中禁用 |
| 「发送」主按钮 | 输入框右侧 | 点击/Enter | 发送消息 | 内容为空或回复进行中禁用 |
| 「经验总结」按钮 | 最右 | 点击 | 对当前会话发起经验起草 | 会话无内容或回复进行中禁用；起草中转圈 |
| 「待确认 N 条」链接 | 经验总结按钮旁 | 有待确认草稿时出现 | 重新打开经验确认弹窗 | 「经验总结」按钮上的角标数字同步显示待确认条数 |

### 经验起草与确认流

**第一步：发起起草。**会话结束后点「经验总结」。AI 两阶段起草：先从对话提取候选经验（含查重比对——与同类目同设备的既有经验对比，判断是新增还是更新），再对候选做复核裁决。起草完成后自动弹出确认弹窗。

**第二步：人工确认（红线：AI 产出必经人工确认才入经验库）。**确认弹窗为宽幅左右分栏：

- 左栏草稿列表：每条草稿一个勾选框（默认全部「采纳」，可改为「丢弃」）；标签标注分类与「新增/更新」性质；质量门未过（缺必填项）的草稿标红显示缺失项（如「缺 严重程度」）；更新类草稿另有「替换旧条目」勾选框（默认不勾——避免 AI 误判更新时误删旧条目）。
- 右栏编辑表单：选中草稿的字段可逐项修改（与 [第 8 章](./08-knowledge-base.md) 经验表单同构：标题/分类/内容/标签/严重程度/故障现象/根本原因/解决办法/预防措施/关联设备），并可「查看原始会话」核对依据。
- 底部按钮：全部采纳/全部丢弃快捷操作，以及「确认采纳 N 条 + 删除 M 条」批量提交（单次原子提交，任一条失败整体回滚）。

确认后的经验立即可被 AI 检索复用；丢弃的草稿删除。有未确认草稿时（关掉了弹窗），随时点输入区「待确认 N 条」回来处理。

### MCP 工具调用

选中带 MCP 绑定的设备（「可调MCP」标签）后，AI 可调用该设备的 MCP 工具。工具调用同样显示为工具调用卡（标题「调用工具 {工具名}」），高风险工具参数会触发与命令同级的确认流。MCP 连接器与包的配置见 [第 10 章](./10-settings.md)。

## 典型流程一：故障排查问答

1. 点「新建会话」。预期左侧出现新会话条目并选中，对话区显示空态「向 AI 助手提问，选择设备后可查询设备信息」。
2. 点右上设备选择器，勾选故障设备（绿色「可执行」标签）。预期收起态摘要显示「已选：{设备名}」。
3. 在输入框描述现象（如「核心交换机-01 的 Gi0/0/1 口频繁 Up/Down，帮我看下原因」），点「发送」。预期消息以浅蓝气泡出现在右侧，随后出现「思考中…」与若干 [预取] 步骤卡。
4. 等待回复完成。预期 AI 回复顶部显示「故障排查」分档标签；若开了预取，回复引用知识库/经验库内容（参考来源区可点开核对）；智能补查模式下若 AI 未查某来源，底部出现对应「未查询：…」灰标签。
5. 追问或让 AI 执行确认命令（进入典型流程二）。

## 典型流程二：让 AI 执行命令

1. 确保目标设备「可执行」且命令首词在白名单内（白名单维护见 [第 10 章](./10-settings.md)）。
2. 对 AI 下达操作意图（如「查看核心交换机-01 的接口流量」）。预期 AI 生成命令提议：
   - confirm 模式：出现审批面板（普通分支），核对「待执行命令」后点「确认执行」；预期面板消失，步骤卡转为「执行中 → 完成」，AI 随后解读输出。
   - 越权命中：面板升级为越权分支（预期目标/实际目标对照），核对差异后「拒绝执行」或「确认执行」。
3. 需要中止时点「停止」红色小按钮。预期立即停止，尾部出现黄色硬停提示条。
4. 事后到日志审计页追溯本次执行的完整记录。

## 典型流程三：沉淀经验

1. 处理完一个有价值的问题后，点「经验总结」。预期按钮转圈，AI 两阶段起草后自动弹出确认弹窗。
2. 左栏逐条决策：默认采纳；不想要的改为「丢弃」；质量门标红的草稿先在右栏补全必填项（缺项时提交按钮禁用）。
3. 更新类草稿按需勾选「替换旧条目」（确认要覆盖旧经验才勾）。
4. 点「确认采纳 N 条 + 删除 M 条」。预期提示成功，草稿进入经验库（有效状态），输入区「待确认 N 条」消失。
5. 下次同类问题，AI 会检索到这条经验——回复的「📗 经验 ×1」徽章即复用凭证，点击可回看。

## Agent 工作方式说明

AI 的自主执行（agent）不是单轮问答，而是受控循环：检索资料 → 生成动作 → 执行 → 依据结果决定下一步，直到给出总结或触发保护。理解以下机制有助于解读界面现象：

| 机制 | 界面表现 | 设计目的 |
| --- | --- | --- |
| 分档预取 | 回复前的 [预取] 步骤卡 + 分档标签 | 按问题类型只取必要资料，控制成本与噪声 |
| 补查 | 中途的 [补查] 步骤卡 | 初次资料不足时补齐依据 |
| 白名单校验 | 审批面板「已拒绝命令」小节 | 命令安全的第一道闸 |
| 越权防护 | 越权确认分支 + 日志「越权记录」 | 目标偏移强制人工把关 |
| 熔断/冷却 | 「已熔断」「冷却中」状态词 | 防止持续冲击故障设备 |
| 硬顶收尾 | 循环停止 + 诚实说明 | 超限即停，不无限消耗 |
| 来源徽章 | 📚/📗/🔧 徽章与明细 | 回答依据可追溯、可点击核对 |

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 使用门槛 | 未配置 AI 服务参数时整页只显示引导提示，不加载会话 |
| 命令白名单 | AI 提议的每条命令先过黑白名单校验：白名单首词直配（confirm 模式仍需确认、auto 模式直执行）；黑名单与白名单外命令被拒或触发越权确认 |
| 越权强制确认 | 越权拦截不受执行模式影响——auto 全自动模式下越权命令照样强制打断确认（日志中标识「自动拦截」） |
| 执行模式 | confirm（每批确认）/ smart（智能）/ auto（自动），在系统设置配置（见第 10 章） |
| Agent 硬顶 | 自主任务有四重硬顶（总步数/时长/连续失败/单设备重试），触顶诚实收尾不无限循环 |
| 熔断保护 | 连续失败过多自动熔断进入冷却，防止对故障设备持续冲击 |
| 输入全局锁 | 一条回复在途时全应用输入锁定（提示条说明原因），防止并发回复竞态 |
| 会话隔离 | 消息、在途步骤卡、思考中指示严格按会话归属，切换不串话不丢失 |
| 经验确认红线 | AI 起草的经验必须人工确认后才发布；手动录入不受此限 |
| 检索设置持久 | 预取开关与补查模式全局持久；故障排查档恒强制补查不可关闭 |
| 换词重查 | 同词已查未命中不重复检索，改为要求 AI 换更具体关键词重查一次；换词后仍同词则告知不再检索（单次有界防循环），智能/强制模式统一 |
| 停止语义 | 停止按钮立即中止（无确认）；已执行步骤保留展示，尾部显示硬停提示条 |

## 常见问题

**Q1：AI 不执行命令，只给文字回答？**
检查三点：设备是否选了「可执行」档（仅问答设备不能执行）；命令是否在白名单（被拒命令会在审批面板「已拒绝命令」或步骤卡中说明）；执行模式与审批流程是否走完（审批面板等待你点「确认执行」）。

**Q2：回复下面出现灰色「未查询：设备」标签？**
这是智能补查模式的知情呈现：AI 判断无需查设备实时数据。想要必定补查，把补查模式切到「强制补查」。

**Q3：审批面板一直占着输入框？**
审批面板必须处理完才消失——点「确认执行」放行，或点「拒绝执行」拒绝。这是设计如此：待确认命令不允许被忽略绕过。

**Q4：切到别的会话再回来，回复还在吗？**
在。回复严格归属其会话：切走时步骤卡暂存，切回合并显示；完成后的消息与轨迹永久保存在会话历史中。

**Q5：「经验总结」点了没反应？**
会话需有内容（空会话按钮禁用）；起草过程可能较长（两阶段 AI 处理），按钮转圈期间请等待；完成后确认弹窗自动弹出。

**Q6：AI 回复的表格/代码显示乱？**
AI 回复按 markdown 渲染；极少情况下模型输出不规范 markdown 会导致排版异常，重问一次通常恢复。

**Q7：怎么让 AI 别再问我确认，直接执行？**
到系统设置把执行模式改为「auto」（理解越权命令仍会强制确认——这是安全底线不可关闭）。日常工作流建议保持 confirm 或 smart。

**Q8：停止后 AI 的半成品回答去哪了？**
已执行步骤保留在消息区，尾部黄条说明「任务进行中被手动停止，未生成总结；已执行步骤保留在上方。」重新提问即可继续。

**Q9：删除会话会连带删掉已确认的经验吗？**
不会。经验一旦确认入库就是独立资产；删除会话只删对话记录。经验的来源会话引用将无法再回看原文。

**Q10：为什么同一个问题两次回答引用的资料不一样？**
检索命中与 AI 判断（智能补查模式）随知识库内容、经验库状态与提问措辞变化；用「参考来源」与徽章核对每次的具体依据即可。

**Q11：多选了 10 台以上设备有什么后果？**
选择器会提示「设备较多，AI 回答质量可能下降」——上下文过多会稀释重点，建议按问题聚焦到相关设备子集。

**Q12：「已熔断」之后还能继续让 AI 执行吗？**
冷却结束后自动恢复；若设备持续故障，先处理设备问题再让 AI 重试，避免反复触发熔断。

**Q13：AI 助手页提示「请先在「系统设置」中配置 AI 服务参数」？**
说明尚未配置模型服务。到系统设置 → AI 配置完成 API 地址与 Key 后回到本页即可正常使用（配置步骤见第 10 章）。

**Q14：会话标题能改吗？**
标题由首条提问自动生成，当前版本不提供手动改名；按内容可辨识为主。

**Q15：回复里出现「已请求换词重查」是什么意思？**
补查时 AI 想用的关键词与之前查过（且未命中）的相同，系统会让 AI 换一个更具体的关键词重新查，而不是同一个词反复查。换词只做一次，若仍相同会直接说明后以现有资料作答。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 会话 | 一次完整对话线程，含消息、步骤卡与轨迹，可随时切回 |
| 未读小圆点 | 其他会话有新回复时的提示点，点入即清除 |
| 设备上下文 | 本次对话选定的目标设备集及其能力档位 |
| 能力三档 | 设备按通道/MCP 配置派生的可执行/可调MCP/仅问答标注 |
| 预取 | 回答前按问题档位自动检索注入资料（[预取] 前缀卡） |
| 补查 | 回答中途发现资料不足时追加检索（[补查] 前缀卡） |
| 强制补查 | AI 判定资料不足必发起补查的模式 |
| 智能补查 | 是否补查由 AI 自行判断的模式（未查源显示灰标签） |
| 换词重查 | 补查关键词与已查词相同时要求 AI 换词重查一次的机制（单次有界） |
| 检索设置 | 输入行首齿轮入口：预取开关 + 补查模式，全局持久 |
| 分档 | 问题自动归类：故障排查/配置查询/知识问答/巡检执行 |
| 工具调用卡 | AI 每个动作的紧凑单行卡，可展开看输入输出 |
| 熔断 | 连续失败过多后暂停执行进入冷却的保护机制 |
| 越权 | 命令目标超出对话设备集/发生跳转/MCP 参数敏感 |
| 审批面板 | 待确认命令出现时替换输入区的内联确认卡 |
| 硬顶 | 自主任务的步数/时长/失败次数上限 |
| 硬停 | 用户手动停止任务后的诚实收尾提示 |
| 经验起草 | AI 从会话提取候选经验的两阶段过程 |
| 采纳/丢弃 | 确认弹窗中对每条草稿的决策 |
| 替换旧条目 | 更新类草稿覆盖同主题旧经验的选项（默认不勾） |
| 输入全局锁 | 一条回复在途时禁止新发送的防竞态机制 |
| 质量门 | 草稿提交前按分类校验必填项（缺项标红禁交） |
| 参考来源 | 回答直接引用的资料清单，可点击回查 |
| 来源徽章 | 📚知识库/📗经验/🔧设备/🔧工具的命中计数标签 |
| 未读提醒 | 他会话有新回复时的蓝色小点与角标机制 |
| 双向核对 | 越权面板的预期目标/实际目标对照布局 |
