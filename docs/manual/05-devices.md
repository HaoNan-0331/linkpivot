# 第 5 章 设备管理

## 功能概述

设备管理是设备台账的唯一维护入口：新增/编辑/删除设备、为每台设备配置四类远程通道凭证（SSH / Telnet / Web 界面 / RDP 远程桌面）、并行测试全部通道连通性、复制设备、处理重名。设备是拓扑节点、AI 上下文、自动发现、ARP 采集等一切功能的数据基础。

## 界面布局

页面标题「设备管理」位于左上角，右上角是「添加设备」主按钮。标题下方依次为：重名提示条（仅存在存量重名时出现）与设备表格。表格从左到右列依次为：设备名称、类型、厂商、型号、IP、连接方式、操作（操作列从左到右四个图标按钮：测试连接、编辑、复制、删除）。表格不分页，直接列出全部设备。

## 逐元素详解

### 设备表格

| 列 | 内容与规则 |
| --- | --- |
| 设备名称 | 全局唯一的设备名（唯一性见「命名全局唯一」小节） |
| 类型 | 路由器 / 交换机 / 防火墙 / 服务器 / 通用 |
| 厂商 | 自由文本，如「华为」「Cisco」 |
| 型号 | 自由文本，如「S5735-L48T4X」 |
| IP | 设备管理地址；允许与其他设备重复（仅黄色警告，见表单规则） |
| 连接方式 | 默认通道大写（如 SSH）+ 已配多通道时右侧小字「+N」后缀；悬停显示「已配通道：」全清单；未配置任何通道显示「—」 |
| 操作 | 测试连接（雷达图标）/ 编辑（铅笔）/ 复制（拷贝）/ 删除（垃圾桶，红色） |

### 操作按钮

| 按钮 | 触发条件 | 行为 | 规则与限制 |
| --- | --- | --- | --- |
| 测试连接 | 点击操作列雷达图标 | 并行探测该设备**全部已配置通道** | 单通道/零通道以轻提示显示结果；≥2 通道弹出顶部居中的通知卡，逐通道显示 ✓/✗ 与结果文案，持续约 8 秒；全部通过 success 样式、部分失败 warning、全败 error；探测期间按钮转圈禁用 |
| 编辑 | 点击铅笔图标 | 打开「编辑设备」表单（回填现状） | 保存事务化，失败整体回滚并提示「操作失败，数据已回滚无变化：…」 |
| 复制 | 点击拷贝图标 | 打开「复制设备」表单，预填源设备全部非凭证字段 | 凭证永不继承（安全红线），须重新输入；IP 与源设备相同会被硬拦（见表单规则） |
| 删除 | 点击垃圾桶图标 | 弹气泡确认「删除设备将同时从拓扑中移除，确定删除？」 | 确认后删除设备并级联移除所有拓扑中的对应节点；事务化，失败回滚 |
| 添加设备 | 右上角主按钮 | 打开「添加设备」空表单 | — |

测试结果的通道文案沿用探活契约：SSH/Telnet 为「连接成功」或具体失败原因（含 errno 中文映射，如「连接超时」「无法访问的主机」类网络错误的人话描述）；Web/RDP 为「端口可达」或失败原因；零通道时提示「该设备未配置登录通道」。多通道汇总行格式「{pass}/{total} 通道连接成功」。

### 设备表单（添加 / 编辑 / 复制共用）

表单弹窗标题按模式显示「添加设备」「编辑设备」或「复制设备」（宽约 600 像素）。上半部为基本信息，下半部为四个通道页签。

**复制模式**：顶部黄色提示「复制自『{源设备名}』——已预填源设备信息（可修改）；密码/密钥不会继承，请重新输入。」四通道开关全部关闭、零回填。

**零通道引导**（从拓扑双击进入时）：顶部黄色提示「该设备尚未配置登录通道——补配任一通道的凭证并保存后，即可双击连接」，并自动定位到推荐页签。

#### 基本信息字段

| 字段 | 必填 | 校验与规则 |
| --- | --- | --- |
| 设备名称 | 是 | 留空提示「请输入设备名称」；失焦实时查重，命中红字提示「名称已存在：{冲突设备名} ({冲突IP})」 |
| 设备类型 | 是 | 下拉五选一：路由器/交换机/防火墙/服务器/通用设备 |
| 厂商 | 是 | 留空提示「请输入设备厂商」，占位「华为、Cisco、H3C...」 |
| 型号 | 否 | 占位「S5735-L48T4X」，与「版本」同行 |
| 版本 | 否 | 占位「V200R021」 |
| 设备 IP | 是 | 占位「192.168.1.1」；与其他设备（排除编辑自身与复制源）相同仅黄色警告「IP 与设备『{设备名}』相同，请确认是否允许」可继续保存；**复制模式下与源设备 IP 相同会被红字硬拦「与源设备 IP 相同，必须修改」** |
| 默认通道 | 否 | 说明文字「双击直连与 AI 执行命令优先使用默认通道」；下拉选项仅列出当前已开启的通道；不选可保存（显示「未配置」）；见「默认通道选择与滑落」小节 |

#### 四通道页签

页签从左到右固定为：SSH、Telnet、Web 界面、RDP 远程桌面。每个页签标题在通道已启用时带一个绿色小圆点（表示「已配置」）。

**每个通道页签顶部是一个启用开关（Switch）**，语义：

- 开关是通道启用/禁用的唯一权威：开着才启用该通道凭证；
- **填了即启用**：在任意凭证字段输入内容，开关自动打开（防止填了凭证却没启用的隐性错误）；
- 清空字段不会自动关闭开关（禁用必须显式拨 off，防误触丢配置）；
- 拨 off 后该通道字段全部置灰（值保留在界面，可拨回反悔）；
- **编辑模式下把原本已配置的通道拨 off**，开关旁出现琥珀色警示「保存后将删除该通道已存凭证」；保存后该通道凭证即被删除。

**SSH 页签字段：**

| 字段 | 说明 |
| --- | --- |
| 端口 | 数字输入，1~65535，占位「22」 |
| 账号 | 登录用户名 |
| 密码 | 密码框。已存密码时占位提示「已存 ****尾4，留空则不修改」（尾4 为已存密码末四位）；编辑未改密时占位「留空则不修改」；留空提交 = 保持原密码不变 |
| SSH Key 文件路径 | 占位「C:/Users/.ssh/id_rsa（可选）」；与密钥内容二选一即可 |
| 或粘贴 SSH Key 内容 | 多行文本。已存密钥时占位「已存密钥（****尾4），留空则不修改；粘贴新内容将覆盖」；新建设备占位示例私钥开头 |

SSH 支持密钥与密码两种认证；同时填写时以密钥优先。

**Telnet 页签字段：** 端口（占位「23」）、账号、密码（占位规则同 SSH）。Telnet 为明文协议，仅用于只支持 Telnet 的旧设备。

**Web 界面页签字段：** Web URL（占位「https://192.168.1.1」）。连接时用系统浏览器打开该地址。

**RDP 远程桌面页签字段：**

| 字段 | 说明 |
| --- | --- |
| 端口 | 占位「3389」 |
| 账号 | 远程桌面用户名 |
| 密码 | 预留字段：加密存储但连接时由系统远程桌面客户端自行提示输入密码（.rdp 文件格式限制，不支持明文密码行）；其余占位规则同 SSH |
| 分辨率 | 占位「1920x1080（可选）」，格式为「宽x高」（字母 x）；留空 = 不指定；格式不符时连接将忽略该值使用默认分辨率 |

#### 凭证「留空=不修改」规则（编辑模式）

编辑已配通道时，密码与密钥内容**永不回填明文**（界面只见过占位提示「已存 ****尾4」），留空提交即保持已存凭证不变；端口、账号、密钥路径、Web URL、分辨率这些非敏感字段会回填当前值，提交时按表单现值写入——把这些字段清空后保存即真实清除该字段。

#### 默认通道选择与滑落

- 默认通道下拉选项永远只包含当前开关开启的通道；
- 现选默认通道被关闭后，表单内自动滑落到固定顺序（SSH > Telnet > Web > RDP）中下一个开启的通道，无提示；
- 全部通道关闭后默认通道置空（显示「未配置」），可保存为零通道设备；
- 不手动选择时，保存由服务端按同样规则收敛（首条已开启通道）。

### 重名提示条与重名设备清单

历史数据若存在同名设备（旧版本未启用唯一约束时产生），设备页顶部出现黄色提示条：「存在 N 组重名设备（共 M 台），处理后自动启用名称唯一防护」，右侧「查看清单」红色小按钮。

点开「重名设备清单」弹窗（宽约 720 像素）：按重名组折叠展示，组标题为「{设备名} ×{台数}」，展开后每台设备一行：IP / 型号 / 厂商区分信息 + 名称输入框（内联编辑）+「保存」按钮（输入为空或与原名相同时禁用）。单台改名即时保存，提示「已改名为『{新名}』」，改完该组即消失。

全部清零后弹窗显示绿色「唯一防护已启用 ✓」与说明「所有重名已处理，数据库唯一索引已自动建立，后续同名保存将被拦截。」提示条同步消失。

## 设备能力与下游功能的关系

设备配置的通道决定了它在其他模块中的可用能力（界面上不直接展示能力字段，但以下功能依赖它们）：

| 通道配置 | 拓扑双击 | 自动发现 | ARP 采集 | AI 执行命令 | AI 设备上下文档位 |
| --- | --- | --- | --- | --- | --- |
| SSH | 可连 | 可参与 | 可作为采集源 | 可执行命令 | 可执行 |
| Telnet | 可连 | 可参与 | 可作为采集源 | 可执行命令 | 可执行 |
| Web 界面 | 可连（浏览器打开） | 不参与 | 不参与 | 不执行 | 仅问答（可检索知识/经验，不能执行命令） |
| RDP 远程桌面 | 可连（远程桌面窗口） | 不参与 | 不参与 | 不执行 | 仅问答 |
| 绑定了 MCP 工具 | — | — | — | 经 MCP 工具操控 | 可调 MCP |

设备能力三要素（有无 SSH、有无 Telnet、有无 MCP 绑定）由后台根据通道配置自动派生，AI 助手选择设备上下文时按此标注档位（详见 [第 7 章](./07-ai-assistant.md)「设备上下文选择器」）。

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 命名全局唯一 | 设备名经归一化（忽略大小写与首尾空白等）后全局唯一：失焦预检 + 保存时服务层事务内硬拦截（双重防线）；冲突错误含对方设备名与 IP |
| 单份复制 | 复制只继承非凭证字段（名称/类型/厂商/型号/版本/IP 可改）；四通道凭证全部需要重新输入——源凭证永不出现在界面 |
| 凭证加密 | 所有密码/密钥内容 AES-256-GCM 加密落库；界面回显永远只有「****尾4」脱敏形态 |
| 通道数上限 | 一台设备最多四通道各一份（每通道一条凭证记录） |
| 端口范围 | 1 ~ 65535 |
| 删除级联 | 删除设备同时从所有拓扑移除其节点，事务化 |
| 保存事务化 | 设备增删改均为单事务：失败整体回滚，界面不落半截数据 |
| 升级自动迁移 | 从旧版本（单通道凭证平铺）升级到当前版本时，历史凭证自动迁移到按通道存储，无需人工处理 |
| IP 重复 | 警告级（黄色）允许保存；复制模式同源 IP 硬拦 |
| RDP 分辨率 | 「宽x高」格式才生效（如 1920x1080），否则忽略 |

## 典型操作流程：添加并验证一台新设备

1. 点右上角「添加设备」。预期弹出「添加设备」表单。
2. 填写设备名称（如「核心交换机-01」）、类型、厂商、IP。预期名称失焦无红色查重提示，IP 无黄色警告。
3. 打开 SSH 页签开关（或直接在端口/账号字段输入，开关自动打开），填端口（默认占位 22）、账号、密码（或密钥）。预期页签标题出现绿色小圆点。
4. 「默认通道」下拉此时应已包含 SSH（表单自动滑落选中）；如需 Telnet 为主可再开 Telnet 页签并改选默认通道。
5. 点「确 定」。预期提示「设备添加成功」，表格出现新行，「连接方式」列显示「SSH」。
6. 点该行「测试连接」图标。预期绿色提示「核心交换机-01: SSH 连接成功」（多通道时为顶部通知卡逐通道 ✓/✗）。
7. 到 [第 4 章 拓扑管理](./04-topology.md) 用画布右下角「+」把该设备加入拓扑，或直接双击拓扑节点验证连接。

## 常见问题

**Q1：编辑设备时密码栏是空的，保存会不会把密码清掉？**
不会。密码/密钥内容留空 = 不修改已存凭证；占位提示「已存 ****尾4，留空则不修改」就是为了表明这一点。想换密码时输入新值提交即覆盖。

**Q2：一台设备能同时配 SSH 和 Telnet 吗？**
能。四通道相互独立，可同时启用任意多类；「连接方式」列会显示如「SSH +1」，悬停可看全清单。

**Q3：测试连接测的是什么？**
对已配置的每个通道做连通性探测：SSH/Telnet 实际尝试登录验证凭证；Web/RDP 探测端口可达性。多通道时并行探测、结果逐通道展示。

**Q4：复制设备后为什么还要填一遍密码？**
安全设计：凭证只在后台加密存储，复制时不透传到界面（防止凭证在界面层流转）；新设备凭证视为全新输入。

**Q5：设备名提示「名称已存在」但列表里没看到同名设备？**
唯一性按归一化名称判定（忽略大小写与空白差异），可能与其他设备名仅在大小写上有别；错误信息会给出冲突设备名与 IP，去改其中一个即可。

**Q6：拨通道开关旁出现橙色字「保存后将删除该通道已存凭证」？**
这是在编辑模式下关闭一个原本已配置的通道的明确警示。确认不需要该通道了再保存；拨回开关即可反悔。

**Q7：删设备会把拓扑弄坏吗？**
不会。删除是事务化级联：设备与其在所有拓扑中的节点一并移除；失败则整体回滚，两边都保持原状。

**Q8：SSH 密钥认证和密码认证填哪个？**
按设备实际支持的认证方式填其一即可；两者都填时密钥优先。密钥可用「文件路径」指向本机私钥文件，或直接「粘贴密钥内容」（完整含 BEGIN/END 行）。

**Q9：RDP 分辨率写了没生效？**
检查格式：必须是「宽x高」形如 1920x1080（中间是字母 x）。格式不符时连接会忽略该值，使用客户端默认分辨率。

**Q10：「连接方式」列显示「—」是什么意思？**
该设备未配置任何登录通道。零通道设备可以保存（作为纯台账记录），但无法双击连接、不参与自动发现与 ARP 采集。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 通道凭证 | 某一类远程通道（SSH/Telnet/Web/RDP）的登录信息（端口/账号/密码/密钥/URL 等） |
| 启用开关 | 每个通道页签顶部的 Switch，通道启用状态的唯一权威 |
| 填了即启用 | 在凭证字段输入内容会自动打开该通道开关的联动规则 |
| 留空不修改 | 编辑时密码/密钥留空提交表示保持已存值不变的语义 |
| 默认通道 | 双击直连与 AI 执行命令优先使用的通道，可手动选择或自动滑落 |
| 滑落 | 默认通道失效时自动降级到固定顺序下一可用通道的规则 |
| 已配圆点 | 通道页签标题上的绿色小点，表示该通道已启用 |
| 归一化查重 | 忽略大小写/空白差异的设备名唯一性判定 |
| 重名清单 | 处理历史存量重名设备的引导弹窗，清零后自动启用唯一索引 |
| 并行探测 | 测试连接同时对全部已配通道发起探测并逐通道报告结果 |
| 事务化 | 多表写入要么全部成功要么全部回滚的数据库原子性保障 |
| 零通道设备 | 未配置任何登录通道的纯台账记录，可保存但不可连接 |
| 尾4 脱敏 | 已存密码/密钥仅展示末四位、其余以星号遮蔽的回显形式 |
| errno 中文映射 | 把操作系统网络错误编号翻译成中文人话描述的对照关系 |
