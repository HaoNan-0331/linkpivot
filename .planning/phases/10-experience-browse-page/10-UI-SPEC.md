# Phase 10 — UI Design Contract

> Visual and interaction contract for the Experience Browse Page (knowledge base「经验」Tab).
> Generated by gsd-ui-researcher; verified by gsd-ui-checker. All copy is 简体中文.
> Design system is **Ant Design 6** — tokens below lock WITHIN AntD defaults (no new design language).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none（Ant Design 既装，无 shadcn — 项目不使用 shadcn gate） |
| Preset | not applicable |
| Component library | Ant Design 6（Table / Tabs / Modal / Form / Select / Switch / Tag / Popconfirm / Empty / Input / Button / Space / Spin / message） |
| Icon library | `@ant-design/icons`（与 KnowledgeBasePage / ReviewConfirmModal 同源） |
| Font | AntD 默认（系统字体栈 14px base） |

> Source: KnowledgeBasePage.tsx + ReviewConfirmModal.tsx 实测既有用量。本 phase 不引第三方 registry，无安全 gate。

## Spacing Scale

沿用项目事实约定（AntD 8-point grid），全部为 4 的倍数：

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tag 间距（list 卡片内 `gap: 4`，ReviewConfirmModal.tsx:256 实测）/ 次级 inline 间距 |
| sm | 8px | Card 内 Card 间距（`marginBottom: 8`）/ Form.Item 间默认 / 行内图标-文字 gap |
| md | 16px | 默认元素间距（filter Space wrap marginBottom / Modal 内 Space marginBottom 12~16） |
| lg | 24px | 页面外层 padding（KnowledgeBasePage `<div style={{ padding: 24 }}` 实测） |
| xl | 32px | —（本 phase 不用） |
| 2xl | 48px | —（本 phase 不用） |

Exceptions:
- **Modal 内 master-detail 左右栏 gap**：`16px`（与 ReviewConfirmModal.tsx:212 `gap: 16` 一致）。
- **左侧列表项**：`padding: 8` + `marginBottom: 4`（ReviewConfirmModal.tsx:233 实测，经验 Tab 列表不沿用此 master-detail 卡片；仅详情回链 Modal 复用）。
- **触控目标**：本 phase 为桌面键鼠操作，无 44px 强制；行操作 Button 一律 `size="small"`（与 KnowledgeBasePage.tsx:359 一致）。

## Typography

锁定 3 sizes / 2 weights（AntD 默认 + KnowledgeBasePage 实测）：

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5715（AntD 默认） |
| Label / Table 表头 / Tag | 14px | 400 (regular) | 1.5715 |
| Emphasis（卡片标题 / 详情字段名 strong / 详情值高亮） | 14px | 600 (semibold) | 1.5715 |

> 说明：本 phase 不引入 Display/Heading 大字号（KnowledgeBasePage 全程 14px，Tab + Card title 由 AntD 内置 14-16px 承载）。错误信息小字（如 error_message）沿用 KnowledgeBasePage.tsx:345 `fontSize: 12` — 视为 secondary text 而非新档位。

## Color

沿用 AntD 默认 token + 项目既有 Tag 色（KnowledgeBasePage STATUS_MAP / ReviewConfirmModal 实测）：

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` 白 | 页面背景 / Card 背景 / Modal 背景 |
| Secondary (30%) | `#fafafa` / Card 边框 `#eee` / 分隔线 `#d9d9d9` | Card 边框 / master-detail 左栏 borderRight `#eee` / 列表项 border `#d9d9d9` / 选中态背景 `#e6f4ff`（ReviewConfirmModal.tsx:235 实测） |
| Accent (10%) | AntD `primary` `#1677ff`（v6 默认） | 见下方 reserved-for |
| Destructive | AntD `error` `#ff4d4f` | 仅：删除按钮 `danger` / Popconfirm 删除确认 / 质量门标红（缺必填项 Tag `red` + 列表项 border `#ff4d4f`）/ error_message 小字 |

**Accent reserved for**（明确清单，不可扩散）：
1. 顶部「新增经验」主 CTA Button（`type="primary"`）。
2. Tab 选中态下划线 / Table 标题 `<a>` 行点击文字（沿用 KnowledgeBasePage.tsx:317 `<a>` 蓝字点行打开详情）。
3. 列表「编辑」「恢复有效」次按钮（`type="default"` + 蓝字图标，与 KnowledgeBasePage 重试按钮同范式）— **不染红**，红只给 destructive。

**Tag 色映射**（本 phase 关键 UI 决策，沿用既有色板，禁止新色）：

| Tag 用途 | `color` 值 | 来源 |
|----------|-----------|------|
| 分类（troubleshooting/最佳实践/产品/环境） | `blue` | ReviewConfirmModal.tsx:257 |
| 严重程度（troubleshooting 类，详见下表语义色） | 见下 | 本 phase 新增（D-10-2 severity 独立明文列筛选/排序） |
| 状态——有效（published 且 invalid_at IS NULL OR > now） | `success`（绿） | 对齐 KnowledgeBasePage STATUS_MAP.ready |
| 状态——已失效（invalid_at ≤ now） | `default`（灰）+ 文案「已失效」 | 失效不染红（destructive 色仅给删除操作，不给状态）；灰表达「不活跃」 |
| 关联设备数量（行汇总） | `default`（灰）或纯文本 | 与 KnowledgeBasePage.tsx:329 纯文本一致 |
| UPDATE / 疑似重复命中 | `orange` | ReviewConfirmModal.tsx:258 |

**严重程度 Tag 语义色映射**（troubleshooting 类专用，对齐 Phase 9 中文化 label，value 存英文不变）：

| severity | Tag color | label |
|----------|-----------|-------|
| critical | `red` | 致命 |
| high | `volcano`（AntD 内置，橙红，区别于 destructive `#ff4d4f`） | 高 |
| medium | `orange` | 中 |
| low | `gold` | 低 |
| info | `blue` | 提示 |

> rationale：5 级 severity 需区分；`red` 留给 critical 顶层，避免与删除按钮 `#ff4d4f` 同色混淆 — 用 `volcano` 给 high 做视觉降级。其余沿用 AntD 内置 preset（无新色值）。

## Copywriting Contract

全部 **简体中文**（项目惯例，与 KnowledgeBasePage / Phase 9 表单中文化一致）。

| Element | Copy |
|---------|------|
| Primary CTA | **新增经验**（顶部按钮，verb+noun，与 KnowledgeBasePage「上传文档」同范式） |
| Tab 标题（KnowledgeBasePage 顶部 Tabs） | **文档** ｜ **经验**（两 Tab 平级，经验非独立一级菜单，D-10-4） |
| 新增入口 tooltip / 无 | 按钮直接打开空表单 Modal（无需额外提示） |
| 搜索 Input placeholder | 「搜索经验标题或正文」（onPressEnter 触发 + 300ms 防抖，对齐 KnowledgeBasePage.tsx:441 范式） |
| 筛选 Select placeholder | 分类：「全部分类」/ 严重度：「全部严重度」/ 状态：「全部状态」/ 设备：「筛选设备」/ 标签：「筛选标签」 |
| 「显示已失效」Switch | label「显示已失效」+ 默认 off（默认视图仅有效经验，D-10-3） |
| Empty state heading | 「暂无经验」 |
| Empty state body | 「AI 对话后点『经验总结』自动沉淀，或点击右上角『新增经验』手动录入。」（两条路径引导，对齐 D-10-1 + Phase 8/9 入口） |
| Error state（列表加载失败） | toast `message.error('加载经验列表失败: ' + 错误信息)`（沿用 KnowledgeBasePage.tsx:127 范式） |
| Error state（无原始会话/会话已不可查） | 复用 SessionMessagesModal「原会话已不可查」边界提示（09-03-SUMMARY 已落地，不重写） |
| 质量门缺必填提示 | 复用 `validateDraft` 错误串：「缺 标题」/「缺 内容」/「缺 严重程度」/「缺 故障现象」/「缺 解决办法」（Phase 9 单一来源，D-10-1 抽组件一并抽出校验） |
| 提交成功（手动新增/编辑） | `message.success('保存成功')`（沿用 KnowledgeBasePage.tsx:233） |
| 标失效成功 | `message.success('已标记为失效')` |
| 恢复成功 | `message.success('已恢复为有效')` |
| Destructive: 物理删除 | Popconfirm `title="确认删除"` + `description="将彻底删除经验『{title}』，操作不可恢复。"` + `okText="删除"` + `cancelText="取消"`，触发按钮 `danger`（沿用 KnowledgeBasePage.tsx:362-368 范式，加「不可恢复」强提示，D-10-3） |
| Destructive: 标失效（软） | Popconfirm `title="标记为失效？"` + `description="失效后将从默认视图剔除，但仍可查/可恢复，不会物理删除。"` + `okText="标失效"` + `cancelText="取消"`（软操作，弱确认即可；强调可恢复降误删焦虑） |
| 列表行操作按钮文案 | 有效经验：「编辑」/「标失效」/「删除」；失效经验：「编辑」/「恢复有效」/「删除」（D-10-3 三能力，按钮按状态切换） |
| 详情 Modal 标题 | `经验详情 - {title}`（对齐 KnowledgeBasePage.tsx:465「文档详情 - {title}」范式） |
| 详情「查看原始会话」按钮 | 「查看原始会话」（复用 ReviewConfirmEditForm.tsx:181 文案 + 复用 SessionMessagesModal 子 Modal 叠层） |

**红线③ copywriting 注意**（重要）：
- 手动新增/编辑是**人工录入**（非 AI 产出），不进 draft 闸口，直 `published`（D-10-1 discretion / CONTEXT.md specifics）。**copy 不得出现「待确认」「草稿」「AI 闸口」类暗示**。空表单 Modal footer 主按钮文案：「保存」（保存即直接 published 入库），**禁止**「确认入库」「发布并待审」等暗示人工审核流程的措辞。
- 标失效/恢复/物理删除三能力 copy 严格区分：失效=软（可恢复）、删除=硬（不可恢复）。文案不可混用「删除」指代失效操作。

## Phase 10 关键交互契约（planner / executor 必读）

> 以下为 CONTEXT.md locked decisions 的 UI 落点，planner 据此拆 task。

### 1. KnowledgeBasePage 改造（D-10-4）
- 顶部新增 `<Tabs items={[{key:'docs', label:'文档', children:<现有内容>}, {key:'exp', label:'经验', children:<ExperienceTab/>}]} />`。
- 默认 Tab = 「文档」（不破坏现有文档库 UX）；「经验」Tab 首次切到时懒加载列表。
- 路由 / 侧边栏不动（仍一级菜单「知识库」下）。
- ExperienceTab 独立组件：建议 `src/components/knowledge/ExperienceTab.tsx`（CONTEXT.md discretion）。

### 2. 列表 Table 列顺序（Claude's Discretion → 锁定）

| # | 列名 | dataIndex | width | render 说明 |
|---|------|-----------|-------|------------|
| 1 | 标题 | title | — | `<a onClick={openDetail}>` 蓝字点开详情 Modal（沿用 KB 范式） |
| 2 | 分类 | category | 100 | Tag `blue` + 中文 label（故障排查/最佳实践/产品/环境） |
| 3 | 严重程度 | severity | 90 | troubleshooting 类显 severity Tag（见色映射）；非 troubleshooting 类显 `—`（灰） |
| 4 | 标签 | tags | — | 多个 Tag `default` 横排（超 3 个折叠为 `+N`） |
| 5 | 关联设备 | (listDevices) | 120 | 显设备数（如「3 台」）+ tooltip 列名；无关联显 `全局`（灰 Tag，沿用 KB.t329） |
| 6 | 状态 | status+invalid_at | 100 | 有效=绿 `success`「有效」/ 失效=灰 `default`「已失效」 |
| 7 | 有效期 | valid_at/invalid_at | 180 | `valid_at ~ invalid_at` 或 `valid_at ~ 至今`（失效则显 invalid_at 红字） |
| 8 | 最后验证 | last_verified_at | 150 | `yyyy-MM-dd HH:mm` 或「未验证」（灰） |
| 9 | 操作 | — | 180 | 见下行操作 |

**行操作**（Space wrap，size="small"）：
- 「编辑」（default + EditOutlined）→ 打开 ExperienceEditForm Modal（复用 Phase 9 表单，预填该条）
- 「标失效」（default，仅 valid 时）→ Popconfirm（软，见 copy）
- 「恢复有效」（default，仅 invalid 时）→ 直接调 `experience:restore`（轻量，message 成功提示）
- 「删除」（danger + DeleteOutlined）→ Popconfirm（硬，不可恢复强提示）

### 3. 筛选 bar 布局（Claude's Discretion → 锁定）
- `<Space wrap style={{ marginBottom: 16 }}>`（沿用 KnowledgeBasePage.tsx:378 容器范式）。
- 左→右顺序：**新增经验**（primary，左锚）→ 搜索 Input（width 240，`allowClear`，onPressEnter+防抖）→ 分类 Select（width 120）→ 严重度 Select（width 120）→ 状态 Select（width 120，有效/已失效二选一）→ 设备 Select（width 160，多选）→ 标签 Select（width 160，`mode="multiple"`，从已有 tags 聚合）→ 「显示已失效」Switch（右锚）。
- 任一筛选变化触发 `loadExperiences()`（防抖 300ms 或 onChange 即触发，与 KnowledgeBasePage.tsx:137 `useEffect([filterDevice, filterCategory])` 范式一致）。
- 「新增经验」放筛选 bar 最左（primary 视觉锚点），与 KB「上传文档」一致。

### 4. Modal 尺寸（Claude's Discretion → 锁定）

| Modal | width | 来源 |
|-------|-------|------|
| 手动新增/编辑表单（ExperienceEditForm） | `640px`（固定宽度，单列表单，对齐 ReviewConfirmEditForm 受控宽度但去除 master-detail 左栏） | D-10-1 抽公共组件 |
| 经验详情 Modal | `900px`（沿用 KnowledgeBasePage.tsx:469 文档详情宽度） | SC5 元数据展示 |
| 原始会话回链 Modal | 复用 SessionMessagesModal（既有尺寸，不重定义） | 09-03-SUMMARY |

> 详情 Modal 内不嵌编辑表单（详情只读）；编辑走独立表单 Modal，避免嵌套混乱。

### 5. 公共组件抽取（D-10-1）
- 从 Phase 9 `ReviewConfirmEditForm.tsx` + `ReviewConfirmModal.tsx` 导出的 `validateDraft` 抽出 **`ExperienceEditForm`**（建议 `src/components/knowledge/ExperienceEditForm.tsx`）：
  - 接受 `initialValue?: Experience`（编辑态预填）/ `onSubmit` / `onCancel`。
  - 字段：标题 / 分类 / 内容 / 标签（mode="tags"）/ troubleshooting 类显 severity+symptoms+root_cause+resolution+prevention（与 ReviewConfirmEditForm 完全一致）/ 关联设备多选 Select。
  - **去除**：`查看原始会话` 按钮（详情 Modal 侧独立入口）、`supersedeOld` Checkbox（手动编辑无 UPDATE 语义）。
  - **质量门**：实时 `validateDraft` 标红 + 提交按钮禁用（与 ReviewConfirmModal 双份校验漂移消除，单一来源）。
  - **手动新增提交**：直 `createExperience({...status:'published'})`（D-10-1 红线③ 例外）。
- Phase 9 ReviewConfirmModal 改为复用此 ExperienceEditForm（task 拆分时 planner 评估是否本 phase 内重构 Phase 9 引用，或留 Phase 9 不动仅共享 validateDraft；优先：本 phase 抽出 + 改 Phase 9 import，保证单一来源）。

### 6. 详情 Modal 元数据展示（SC5）
`<Modal width={900} footer={null}>`，内容：
- 顶部 Space：标题（strong 600）+ 状态 Tag + 分类 Tag + severity Tag。
- 元数据行（strong label + 值）：来源会话（source_session_id 截短 + 「查看原始会话」按钮，复用 SessionMessagesModal）/ 关联设备（设备名列表）/ 复用次数（reuse_count）/ 最后验证（last_verified_at）/ 有效期（valid_at ~ invalid_at）/ 创建时间 / 更新时间。
- 正文（content，pre-wrap，maxHeight 400 overflow auto）。
- troubleshooting 类：显 attrs 模板字段块（故障现象 / 根本原因 / 解决办法 / 预防措施），每字段 strong label + 值。
- 底部 Space：编辑（开 ExperienceEditForm Modal）/ 标失效或恢复 / 删除（Popconfirm）。
