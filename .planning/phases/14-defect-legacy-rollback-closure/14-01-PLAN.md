### 遗留库向后兼容语义（CLAUDE.md 硬约束，需文档化）
遗留库 = 升级前已有历史 binding 行的老库（`user_version ≤ 11`，ip_mac_bindings 已有存量行）。v12 迁移加 `is_baseline` 列默认 0，故存量行升级后 `is_baseline=0`（未基线）。本 phase 首次基线机制对遗留库的预期行为：
1. **存量 IP 不误报为 new_ip**：遗留库首次扫描喂某存量 IP（mac 不变）→ 走 entryTx 的 `currentBinding` 分支（存量 active binding 命中）→ 只 `stmtUpdateLastSeen.run(now, id)` 更新 last_seen，**不进 else 分支**，不调 recordChange('new_ip')，不落 ip_mac_changes（向后兼容核心不变量，老库升级后不刷屏报全量 IP 为 new_ip）。
2. **后置基线 UPDATE 纳入存量行**：runBatch 整批事务结束后，processARPEntries 入口读到 `hasBaseline=false`（首次扫描），执行 `UPDATE ip_mac_bindings SET is_baseline = 1 WHERE is_baseline = 0`——此 UPDATE 会把**遗留库所有现存存量 binding 行也置 is_baseline=1**（本次扫描喂的存量 IP + 本次未喂的存量 inactive 行，只要 is_baseline=0 全置 1）。语义：**首次扫描把当前所有现存 IP（含遗留存量）纳入基线，之后新增 IP 才报 new_ip**。这是预期行为（老库升级后第一次扫描即确立基线），executor 须在代码注释明示、SUMMARY 记录此语义供后续运维理解。
3. **遗留库首次后报新增 IP**：基线建立（含存量行被置 1）后，第二次扫描喂全新 IP（库里无任何 binding）→ 走 else 分支 + hasBaseline=true → 报 new_ip（与 fresh-install 库一致，向后兼容）。
