# Summary: P1 medium 风险加固

## What

- **P1-a auth:* 脱敏**：4 个登录前 handler（getCaptcha / login / isFirstRun / initAdmin）改 `safe()` 包装，异常经 `sanitizeMessage` 脱敏后再 reject 渲染层（与 `authGuard.ts:44` 设计注释一致，兑现脱敏红线；不鉴权——登录前 handler 设计如此）。
- **P1-b dev/prod 锚定**：main.ts 两处 `process.env.NODE_ENV === 'development'` → `!app.isPackaged`。消除「打包流程误带 dev 标志则 CSP 失效」的隐式依赖（SEC-3 风险点），`app.isPackaged` 是 Electron 运行时可靠标志。
- **P1-c native rebuild 显式**：package.json 加 `rebuild:native`（`electron-rebuild -f -w better-sqlite3 -w ssh2`）接入 `electron:build` 前置；新增 `.github/workflows/build-smoke.yml` windows 冒烟 job（npm ci + rebuild + build + test + 验证 `.node` 存在），防 DEP-1 ABI 静默失配。

## Verify

- esbuild `build:electron-main` 1.8mb ✓
- vitest **55/55** ✓（safe 包装器已有 `authGuard.test.ts` 覆盖：脱敏/鉴权/截断）
- `tsc -p tsconfig.web.json --noEmit` exit 0 ✓

## Note

- CI workflow（`.github/workflows/build-smoke.yml`）是新文件，**push 到 GitHub 后才触发**。冒烟只跑到 build + test + native 验证，不含 electron-builder 打 installer（CI 慢 + 需签名配置，留作后续扩展）。
- `rebuild:native` 只 rebuild better-sqlite3 + ssh2（有 native 的包）；telnet-client 是纯 JS（CONCERNS 已订正，非 0.1.2 quick task 误标的 native）无需 rebuild。
- `app.isPackaged` 在 dev（`electron:dev`）为 false → 走 dev 路径（vite loadURL + CSP skip 兼容 HMR）；打包后 true → production 路径（严格 CSP）。行为与原 NODE_ENV 判断一致但更可靠。
