## Background

ai-telnet-exec-routing debug 修了 AI 执行命令按 connectionType 分流（telnet 能连了）。但用户实机验证发现：`display current-configuration`（华为，长输出）只返回第一屏（版本 + sysname + 开头），接口/VLAN/路由全丢。

## Root Cause

`electron/utils/telnetExec.ts executeTelnetCommand` 直接 `connection.exec(command)`，`shellPrompt /[>#]/`，**无分页处理**。华为长输出默认分页（`---- More ----`），telnet-client exec 不自动翻页 → 设备在第一屏暂停 → 数据流静默 → exec 误判命令结束 → 截断第一屏。arpCollector 用短命令（display arp all）未暴露。

## Fix（最小变量，先治主因）

exec 真命令前先发「关闭分页」命令（运维自动化标准做法）：
- 华为/H3C → `screen-length 0 temporary`
- 思科/锐捷 → `terminal length 0`
- default → `screen-length 0 temporary`

`shellPrompt /[>#]/` 暂不动（systematic-debugging Phase 3 一次一变量），先修分页主因，实机验证后若仍截断再精确化。

## Tasks

### Task 1: telnetExec.ts 加 disablePaginationCmd 选项
- `TelnetExecOptions` 加 `disablePaginationCmd?: string`
- connect 后、exec 真命令前，若提供则先 `await connection.exec(disablePaginationCmd)`（try/catch 忽略输出与不支持错误，不阻断主命令）

### Task 2: ai.ts telnet 分支按 vendor 选关闭分页命令
- 加 helper `pickDisablePaginationCmd(vendor)`：cisco/ruijie → `terminal length 0`，否则 `screen-length 0 temporary`
- `executeCommandsOnDevice` telnet 分支 options 加 `disablePaginationCmd: pickDisablePaginationCmd(device.vendor)`（runOne 外算一次）
- arpCollector 不传（短输出保持原行为）

### Task 3: 补 ai.telnetRouting.test.ts 分页命令 case
- huawei vendor → options.disablePaginationCmd === 'screen-length 0 temporary'
- cisco vendor → 'terminal length 0'
- ssh 设备 → telnetExecSpy 不被调用（已有，无需改）
- 现有 case 1（无 vendor）→ default 'screen-length 0 temporary'（toMatchObject 不破坏）
