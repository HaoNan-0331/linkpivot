## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer→IPC→service | untrusted renderer 经 experience:list opts（含 search/severity/tags/deviceId[]）与 experience:restore(id) 跨信任边界调用 main 进程 |
| service→DB | listExperiences 拼 SQL 查 experiences 表（含新 severity 明文列 + exp_device_rel device_count 子查询 + deviceId 多选 IN 占位 JOIN） |
| main→renderer | rowToExperience 回填 severity（明文，非密文，非凭证）+ device_count（计数，非敏感）经 IPC 返 renderer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | listExperiences search/severity/tags/deviceId[] 拼接 | mitigate | 参数化占位：search/severity `conditions.push('e.title LIKE ?')` + `params.push(kw)`；deviceId 多选用 `IN (` + `deviceIds.map(()=>'?').join(',')` + `)` 占位列表（参数化，非拼接值）；tags OR-join `ors.map(()=>'e.tags LIKE ?')`；禁止字符串拼接用户输入；SQL 注入面闭合；vitest Test 5/6/7 验证多选/筛选行为 |
| T-10-02 | Spoofing | experience:restore IPC | mitigate | 经 `secure(...)` 包装（鉴权 + 异常脱敏），未登录 throw '未登录或会话已过期'，与既有 13 channel 一致 |
| T-10-03 | Elevation | restoreExperience 绕 CR-01 update 白名单改 status | mitigate | 受控接口模式（与 invalidate/incReuseCount/touchLastVerifiedAt 同模式），只暴露清 invalid_at + status='published' 两字段，不开放任意 update；status 直回 'published' 不接受 renderer 入参 |
| T-10-04 | Information | rowToExperience severity 明文 + device_count 回填 | accept | severity 是非敏感元数据（critical/high/...），device_count 是非负整数计数，均非凭证/IP/MAC，明文返 renderer 不违 SEC-02；attrs_enc 仍 decField 回填后 delete 不外泄密文 |
| T-10-05 | Tampering | createExperience status? 入参 | mitigate | 默认 'draft' 保 Phase 7-9 AI 起草不变；renderer 手动新增传 'published' 是设计意图（D-10-1 红线③ 例外：人工录入非 AI 产出），AI 起草路径（Phase 8）不传 status 仍走 draft 闸口 |
| T-10-06 | Repudiation | restore 不记审计 | accept | 单机桌面工具，updated_at 自动刷新（datetime('now','localtime')），无独立审计需求；与 invalidate 同级别（invalidate 也只刷 invalid_at + updated_at） |
| T-10-17 | Denial | device_count 子查询性能 | accept | 单机 sqlite + 经验量级小（单机桌面工具），相关子查询 `(SELECT COUNT(*) FROM exp_device_rel WHERE experience_id=e.id)` 在 exp_device_rel 有索引时 O(log n) per row，零 N+1（单次 SQL 带出），优于前端批量 listDevices enrichment；CLAUDE.md「优先最优秀方案」选 SQL 子查询方案 |
