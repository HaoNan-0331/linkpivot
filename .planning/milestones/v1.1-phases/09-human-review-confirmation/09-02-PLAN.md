      throw new Error(`批量上限 ${MAX_BATCH} 条（或入参无效）`)

  ipcMain.handle('experience:getSessionMessages', secure((_e, sessionId: string) => {
    if (!sessionId || typeof sessionId !== 'string') {
      throw new Error('sessionId 无效')
    }
    return getSessionMessages(sessionId)
  }))

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → IPC channel（confirmDrafts/listDrafts/getSessionMessages） | untrusted renderer 入参跨 contextBridge 进入 main，必经 secure 鉴权 + 异常脱敏 |
| IPC → service（已信任 main 内） | main 内调用，但批量入参需校验上限 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Spoofing | experience:confirmDrafts/listDrafts/getSessionMessages 未鉴权调用 | mitigate | 全 channel 经 secure 包装（authGuard 鉴权 + sanitizeMessage 异常脱敏），未登录 throw '未登录或会话已过期'（延续 Phase 7 SEC-01 基线） |
| T-09-06 | Tampering | experience:confirmDrafts 入参 drafts[] 篡改/超大批量 | mitigate | IPC 层校验 Array.isArray + drafts.length > MAX_BATCH(1000) throw，与 service 层兜底校验双层防御 |
| T-09-07 | Information Disclosure | experience:getSessionMessages 异常透出内部堆栈 | mitigate | secure 包装经 sanitizeMessage 脱敏异常 message 后透出 renderer（authGuard 既有机制，无需额外代码） |
| T-09-08 | Denial of Service | experience:listDrafts / getSessionMessages 高频调用拉满 DB | accept | 经 secure 鉴权后单机运维场景，listDrafts 内 MAX_BATCH 截断、getSessionMessages 单 sessionId 查询天然有界；无多用户洪水攻击面 |
</threat_model>
