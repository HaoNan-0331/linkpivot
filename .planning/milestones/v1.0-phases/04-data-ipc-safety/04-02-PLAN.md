    1. **先获取用户保存路径**（复用 dialog.showSaveDialog，与 saveCSV 同逻辑），拿到 filePath；若 canceled 返回 null。把这个"先问路径"提取为本方法内部步骤（不再走 saveCSV 的 lines 数组）。
    2. **空表检查**：先 `SELECT COUNT(*) as c FROM arp_entries`，若 0 抛 `'没有 ARP 数据可导出'`（保持原错误语义）。
    3. **写 header + BOM 一次**：`writeFile(filePath, BOM + 'IP地址,MAC地址,VLAN,接口,最后采集时间' + '\n', 'utf-8')`。其中 BOM = 直接从 exportService.ts line 80 复制的那个 UTF-8 BOM 字面量（与既有 saveCSV 完全一致，Excel 正确识别中文表头）。**执行时打开 exportService.ts line 80 复制其 BOM 字面量，不要手敲、不要省略。** import 已有 writeFile from 'fs/promises'。
    4. **分批流式读 + append**：用固定批大小常量 `ARP_BATCH_SIZE = 1000`，循环：
       ```typescript
       const ARP_BATCH_SIZE = 1000
       let offset = 0
       for (;;) {
         const batch = db.prepare('SELECT ip, mac, vlan, interface, MAX(collected_at) as collected_at FROM arp_entries GROUP BY ip, mac ORDER BY ip LIMIT ? OFFSET ?').all(ARP_BATCH_SIZE, offset) as any[]
         if (batch.length === 0) break
         const chunk = batch.map(row => [row.ip, row.mac||'', row.vlan||'', row.interface||'', row.collected_at||''].map(csvEscape).join(',')).join('\n') + '\n'
         await appendFile(filePath, chunk, 'utf-8')
         offset += ARP_BATCH_SIZE
       }
       ```
       - import `appendFile` from 'fs/promises'（与 writeFile 同模块）。
       - **SQL 等价性关键**：原 SQL 是 `SELECT DISTINCT ip, mac, vlan, interface, MAX(collected_at) ... GROUP BY ip, mac ORDER BY ip`。分批查询必须用**完全相同的 SELECT/GROUP BY/ORDER BY** + `LIMIT ? OFFSET ?`，才能保证分批拼接后结果集与原全量逐行等价（OFFSET 跨批边界正确）。不得改 GROUP BY 或 ORDER BY。
       - 每批 chunk 末尾加 `\n`，header 也以 `\n` 结尾，拼接后行分隔符一致（避免批边界缺换行）。
    5. 返回 filePath。
    6. 保留 `csvEscape`（line 22-25）原样复用 —— 每行字段转义逻辑不变，保证 CSV 内容等价。
    7. `saveCSV`（line 73）**保留不动**（exportChanges/exportNetworkUsage 仍用它；不在本 plan scope 改这两个）。

    **常量**：`const ARP_BATCH_SIZE = 1000`（文件顶部或方法内）。1000 行/批 = 单批字符串 ~几十 KB，内存峰值恒定。
